# Contributing / Contribuindo

## English

Contributions that improve Fluxium are welcome. The project is developed in the open, and pull requests are the preferred way to propose changes to this upstream repository.

1. For a substantial change, open an issue first to discuss the problem and proposed scope.
2. Create a focused branch and follow the project's [Specification Driven Development process](docs/ai/specification-driven-development.md) for product features.
3. Add or update tests and documentation relevant to the change.
4. Open a pull request against the upstream repository. Describe the motivation, behavior change, tests run, documentation updates, and any known limitations.
5. Address review feedback. Maintainers decide whether and when a contribution is merged; submitting a pull request does not guarantee acceptance.

By submitting a contribution, you confirm that you have the right to submit it and agree that it is distributed under the project's **AGPL-3.0-only** license. You retain copyright in your contribution; this guide does not transfer copyright ownership.

The license does not require fork maintainers to submit changes to this upstream repository or keep their forks synchronized. AGPL-3.0 has separate source-availability requirements for covered distribution and remote network interaction; see [LICENSE](LICENSE) for its terms.

## Português

Contribuições que melhorem o Fluxium são bem-vindas. O projeto é desenvolvido de forma aberta, e pull requests são o caminho preferencial para propor alterações a este repositório principal.

1. Para mudanças substanciais, abra uma issue primeiro para discutir o problema e o escopo proposto.
2. Crie uma branch focada e siga o [processo Specification Driven Development](docs/ai/specification-driven-development.md) para funcionalidades de produto.
3. Adicione ou atualize os testes e a documentação relevantes para a mudança.
4. Abra um pull request direcionado ao repositório principal. Descreva a motivação, a mudança de comportamento, os testes executados, as atualizações de documentação e limitações conhecidas.
5. Responda aos comentários da revisão. Os mantenedores decidem se e quando uma contribuição será integrada; enviar um pull request não garante aceitação.

Ao enviar uma contribuição, você confirma que tem o direito de submetê-la e concorda que ela seja distribuída sob a licença **AGPL-3.0-only** do projeto. Você mantém os direitos autorais da sua contribuição; este guia não transfere a titularidade dos direitos autorais.

A licença não obriga responsáveis por forks a enviar alterações a este repositório principal nem a manter seus forks sincronizados. A AGPL-3.0 tem obrigações próprias de disponibilização do código-fonte em determinadas formas de distribuição e interação remota; consulte os termos em [LICENSE](LICENSE).
